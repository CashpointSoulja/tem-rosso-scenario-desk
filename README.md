# Rosso Scenario Desk

**Independent concept by Ayo Ahmed. Not affiliated with tem.** It runs on synthetic data and fictional prices. It isn't tem's or Rosso's model, it uses no live prices, and it makes no trades.

This is a browser-only scenario desk for one synthetic settlement day on a small two-sided energy portfolio, with two demand assets and two generators. You load half-hourly forecast and actual data, check whether the data can support an answer, compare a **baseline**, a **demand spike** and a **generator outage**, trace any number back to its CSV line, and export a decision memo and scenario CSV.

- Live demo: Cloudflare Workers static assets (free plan). The URL is in the repository "About" link
- Walkthrough video: [media/walkthrough.mp4](media/walkthrough.mp4) (70 s, voiced, captions in [media/walkthrough.srt](media/walkthrough.srt))

## The 30-second version

Forecasts are sometimes wrong, and sometimes the data is simply missing. Those are different problems, and mixing them up costs money. This desk takes a day of forecast and metered data and tells you three things separately: how complete the data is, how wrong the forecast was where we do have data, and what a demand spike or a generator outage would have cost under prices you can see and change. If readings are missing it refuses to give a total instead of pretending the gap is zero. A customer, whether a business or a generator, cares because those errors become imbalance costs, and a supplier that can see and fix them early can keep prices lower and more predictable.

## ELI5

Imagine you promised your friends you'd bring exactly 10 apples, and you planned it from a guess. If you bring 8, you have to buy 2 more at the last minute at a high price. If you bring 12, you have to sell 2 cheaply. This tool works out how many apples you were off by every half hour, and what that would cost. If someone forgot to count the apples in one basket, it says "I don't know yet" instead of guessing that the basket was empty.

## How to use it

1. **Load a day.** Pick one of the four seeded examples or upload a CSV in the same format ([schema](docs/DATA.md#schema)).
2. **Checks.** Coverage (are the readings there?) and forecast error by model version (how wrong was it?) are shown side by side. Stale, conflicting or model-changed inputs go to **manual review**, and you choose what happens to each.
3. **Scenarios.** Three cards: Ready, Needs review, or Blocked. Click any bar, or focus it and press Enter, to see the exact source rows and the transforms applied.
4. **Assumptions.** Change the spike size and window, the outage asset, window and detection lag, the fictional prices, or the stale threshold. Everything recalculates. You can reset the assumptions on their own.
5. **Trade-offs.** Outage cost for each detection lag, and ranked signals in money terms.
6. **Export.** Decision memo (Markdown) and scenario CSV, both carrying source row ids, the file fingerprint, assumptions, review decisions and blockers.

| Seeded example | What it shows |
|---|---|
| Clean day | All 192 slots covered. All three scenarios conclude |
| Missing meter batch | 7 missing slots. Every scenario is **blocked**, never zero-filled |
| Resend + model change | Conflicting resend, stale forecasts, model switch. Needs 3 review decisions before it concludes |
| Clock-change day | 25 Oct 2026 with 50 settlement periods. Concludes |

## What is simulated

- All assets, readings, forecasts, model names and timestamps are fictional. They're generated by `scripts/make-fixtures.mjs` with a fixed seed.
- Prices are fictional assumptions (default £180/MWh peak and £75/MWh off-peak, with a 20% short premium and 40% long spill loss).
- The imbalance and cost formulas are deliberately simple and fully published in [docs/DATA.md](docs/DATA.md#formulas). They don't represent how tem or Rosso calculate anything.
- There's no ML in this app. "Forecast" values are columns in the CSV.
- Nothing is sent anywhere. Files are parsed in your browser and nothing is stored.

## Run locally

```bash
npm ci
npm test            # unit + edge-case tests (vitest)
npm run build       # typecheck + production build
npm run preview     # serves dist/ on http://localhost:4173
npm run flow        # interaction check at 1366 / 820 / 390 px (needs preview running)
npm run fixtures    # regenerate the deterministic CSV fixtures
```

Requires Node 20+.

## Deploy (Cloudflare, free plan)

The app is a static build with no backend and no secrets. `wrangler.jsonc` serves `dist/` as Workers static assets. Connect the repository in the Cloudflare dashboard (Workers & Pages → Create → Import a repository), with build command `npm run build` and deploy command `npx wrangler deploy`. `.github/workflows/ci.yml` runs the tests and the build on every push.

## Known limits

- One settlement day per file. Fixed schema. No contracted position separate from the forecast.
- Flat reference prices. No dual cash-out, no intraday re-trading, no partial outages.
- No backend. The review log exists only in the exported memo.
- The chart scrolls horizontally inside its card on narrow screens. That's intentional, so that every period stays readable.
